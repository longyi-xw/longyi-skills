# 全球新闻总结 + 市场分析

在用户指定的时间窗口内，联网检索主要经济体的市场新闻、政策变动、发展方向与重大灾害事件，产出两部分内容，渲染进同一份 HTML 报告：

1. **新闻总结**：发生了什么。只转述事实与各方公开表态，读者几分钟内就能掌握这段时间的重点。
2. **市场分析**：这些事实合起来说明市场处在什么环境、什么周期位置、释放了哪些信号、存在哪些风险。只分析局势，不给投资方案。

## 两条底线

**新闻只能来自本次检索。** 模型训练数据有截止日期，凭记忆写出的“本周新闻”要么过时，要么是编造的，而读者会拿它做判断。每一条新闻、每一个数字都必须对应本次检索到的、发布日期在窗口内的来源。没有联网搜索能力时，直接告诉用户“当前环境无法联网检索，无法生成新闻报告”，不要用旧知识凑一份。

**事实和分析分开放。** 新闻区只放可核实的事实（谁、何时、做了什么、数字是多少、谁说的）；判断、推断、因果解读都放进分析区，并标明依据和反向证据。整份报告不出现买卖、加减仓、目标价、仓位比例之类的投资建议。

## 工作流

### 第 1 步：确定时间窗口

先取得当前日期（环境信息里通常有；没有就运行 `date`），把用户的说法换算成**绝对日期区间**，写进报告。区间含首尾两天，默认按北京时间（UTC+8）计算，用户另有指定时从其指定。

| 用户说法 | 窗口 |
|----------|------|
| 未指定 | 近 7 天：今天往前推 6 天至今天 |
| 今天 / 今日 | 今天 |
| 一天 / 近一天 / 24 小时 | 昨天至今天（覆盖跨时区的隔夜事件） |
| 本周 / 上周 | 本周一至今天 / 上周一至上周日 |
| 近 N 天 | 今天往前推 N−1 天至今天 |
| 一个月 / 近一个月 | 近 30 天 |
| 本月 / 上个月 | 本月 1 日至今天 / 上月整月 |
| 10 月 1 日到 5 日 | 按原样，未写年份取最近一次已发生的日期 |
| 10 月 1 日、3 日、5 日 | 离散日期，写入 `meta.period.days` |

说法含糊（如“这几天”）时取一个合理值（近 3 天），并在报告的方法说明里写明，不必为此追问用户。窗口内若有主要市场休市（春节、国庆、美国感恩节等），在市场快照的备注里说明。

### 第 2 步：确定检索范围

默认覆盖以下经济体，用户点名缩小或扩大范围时以用户为准：

- **核心**：美国、中国、俄罗斯、欧元区（含德、法）、日本、英国、印度
- **视当期事件纳入**：中东与 OPEC+、韩国、巴西、澳大利亚、加拿大、东盟等
- **全球性**：IMF、世界银行、OECD、WTO 等机构动态，大宗商品，跨国地缘事件

每个经济体按以下维度检索：

| 维度 | 内容 |
|------|------|
| 货币政策与金融监管 | 利率决议、会议纪要、官员讲话、流动性操作、金融监管新规 |
| 财政与产业政策 | 预算、刺激计划、税收、产业补贴、监管与反垄断 |
| 经济发展方向 | 五年规划、政府工作报告、国家战略、重大改革 |
| 宏观数据 | GDP、CPI/PPI、就业、PMI、零售、工业、外贸、信贷 |
| 金融市场 | 股、债、汇、大宗商品的区间表现与重大异动 |
| 贸易、制裁与地缘 | 关税、出口管制、制裁、冲突、选举、外交谈判 |
| 自然灾害与突发事件 | 地震、台风/飓风、洪水、干旱、山火、疫情、重大事故，仅收录对经济活动、供应链或价格有可观察影响的 |

各经济体的权威来源、检索语句模板、检索预算和日期核实方法见 `references/search-playbook.md`。**开始检索前先读它。**

### 第 3 步：检索与核实

按“先广后深”的顺序：

1. **广度扫描**：先搜窗口内的全球市场周报/日报和各国财经要闻汇总，建立事件候选清单。
2. **逐区逐维补查**：按上表的维度矩阵，中英文各查一遍；涉及俄罗斯时补充俄语或俄方通讯社来源。
3. **深读核实**：对候选清单里的重要条目打开原文，核对事件日期、关键数字和表态原话。

核实时注意：

- **日期**：搜索引擎经常返回往年同期的旧文。以原文显示的发布日期和事件发生日期为准，两者都要落在窗口内。分析需要引用的窗口外事件（如上月的央行决议）可以作为背景条目收录，但必须标注 `background: true`。
- **来源分级**：官方发布 > 通讯社（路透、彭博、美联社、新华社、塔斯社等）> 主流财经媒体 > 其他。聚合站和自媒体只当线索，要追溯到原始来源。
- **交叉核对**：利率、数据等关键数字，以官方发布为准，或由两个独立来源核对一致。只有单一来源的条目标记为“单一来源”。
- **合并去重**：同一事件的多篇报道合并成一条，挂多个来源。
- **立场差异**：对有争议的事件（如冲突、制裁、贸易争端），分别注明各方说法及出处，不替任何一方下结论。

检索过程中随手记录每个候选条目：日期、地区、类别、标题、事实要点、关键数字、来源（媒体名 + 标题 + URL + 发布日期）。这份记录就是后面生成报告 JSON 的素材。

### 第 4 步：筛选与排序

重要性按客观标准打分，不按“我觉得重要”：

| 等级 | 标准 |
|------|------|
| ★★★ | 直接改变主要经济体宏观政策（利率决议、大规模财政措施、关税/制裁调整），或引发主要指数单日变动超过约 1% 等全球性市场反应，或造成重大经济损失/关键商品供应中断的灾害 |
| ★★ | 影响某一地区或行业的政策与事件；重要但符合预期的数据发布 |
| ★ | 有参考价值的背景信息 |

条目数量参考：一天 8–15 条，一周 15–30 条，一个月 25–50 条（一个月时侧重 ★★★ 与 ★★）。各核心经济体都要查到；某经济体在窗口内确实没有值得收录的动态时，在方法说明里写“未检索到重要动态”，不要为凑数降低标准，也不要为了某种叙事只挑一类新闻。

### 第 5 步：撰写新闻总结

逐条按“时间—主体—事件—关键数字—来源归属”写，读者不看原文也能知道发生了什么。要点：

- 用数字代替形容词：写“下跌 3.2%”，不写“暴跌”；写“高于路透调查预期的 2.1%”，不写“大超预期”。
- 观点和表态都要归属：“美联储主席鲍威尔在发布会上表示……”“据路透社报道……”。
- 不替来源补因果：来源没说 A 导致 B，就只写“同期”。
- 不写“这意味着……”“标志着……”，这类解读放到分析区。
- **核心要点**（报告开头 4–8 条）也只写事实，按重要性排列，每条挂上对应条目的引用。

完整的措辞规范、情绪词替换表和正反例见 `references/writing-rules.md`。

### 第 6 步：市场分析

分析目标是让读者快速看懂当前局势，不是告诉读者买什么。依次回答五个问题：

1. **环境**：主要经济体处于怎样的增长与通胀组合？政策取向（货币、财政）是收紧、宽松还是观望？流动性和外部环境如何？
2. **状态**：风险偏好在升还是降？波动水平如何？股、债、汇、商品之间的走势是相互印证还是背离？
3. **周期**：各主要经济体分别处在经济周期、货币政策周期、信用/库存周期的什么位置？依据是什么？
4. **信号**：本期新闻释放了哪些政策信号、数据信号、价格信号、事件信号？每个信号的方向、强度、置信度，以及反向证据是什么？
5. **情景与风险**：基准、上行、下行情景分别是什么，靠哪些触发条件和观察指标来判断？主要风险有哪些？在这样的环境下，有哪些通用的风险规避思路？

写分析时：

- **每个判断都要能回溯**到新闻条目或市场数据（用 `[[条目id]]` 引用），没有依据的判断不写。
- **每个信号都要写反向证据**，暂未发现就写“暂未发现明显反向证据”。只写支持性证据的分析就是在下结论。
- 置信度只用“高/中/低”，情景可能性用“相对较高/中等/较低”这类定性词，不给精确概率。
- 风险规避思路只能是通用的风险管理方向（控制杠杆与集中度、关注汇率敞口、预留流动性、了解对冲工具及其成本等），**必须对应本期识别出的具体环境特征**，不点名具体标的，不给仓位比例。环境平稳、没有明显风险时可以少写或不写，不要硬凑。

各项指标怎么读、各经济体的周期线索、信号提取方法和风险规避思路库见 `references/analysis-framework.md`。

### 第 7 步：生成 HTML 报告

报告模板是 `assets/report-template.html`。它由数据驱动：页面结构、样式和交互都已写好，只需提供一份报告数据 JSON，缺少的模块会自动隐藏。

1. 按 `references/report-schema.md` 编写报告数据，保存为 `market-brief-<开始日期>_<结束日期>.json`（单日就只写一个日期）。默认存放在当前工作目录，用户指定了目录就放在那里。
2. 运行构建脚本（只依赖 Python 标准库）：

   ```bash
   python <本技能目录>/scripts/build_report.py market-brief-2026-10-01_2026-10-07.json -o market-brief-2026-10-01_2026-10-07.html
   ```

   脚本会校验日期是否在窗口内、引用是否成立、来源是否齐全，并检查新闻区的情绪化措辞和分析区的投资建议措辞。**错误必须修复**；告警逐条看，能改的改，确属引语原文的保留。
3. 没有 Python 时：复制模板，把 `<script type="application/json" id="report-data">` 里的示例 JSON 整体替换成报告数据（字符串里的 `<` 写成 `\u003c`，否则可能提前截断脚本块），并删除 `meta.demo`。
4. 当前环境无法写文件（纯聊天场景）时：按报告的章节顺序直接输出 Markdown，内容规范不变。

### 第 8 步：交付

在对话里简短回复：报告文件路径、统计区间、3–5 条最重要的事实，以及检索缺口（如某国数据未能获取）。不要把整份报告再贴一遍。

## 交付前自检

- [ ] 每条新闻都有来源，事件日期都在窗口内（或已标注为背景）
- [ ] 关键数字来自官方发布或经两个独立来源核对
- [ ] 新闻区和核心要点里没有评价、推测和情绪词
- [ ] 有争议的事件已列出各方说法及出处
- [ ] 每个分析判断都能回溯到条目，每个信号都写了反向证据
- [ ] 全文没有买卖、加减仓、目标价、仓位比例等投资建议
- [ ] 构建脚本无错误，告警已逐条处理
- [ ] 方法说明里写清了窗口、范围、检索局限与数据缺口
